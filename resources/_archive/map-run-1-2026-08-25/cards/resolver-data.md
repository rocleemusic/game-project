## What it is
The resolver's input layer: `scene-graph.json`, `screen-specs.json`,
`seams.json`, `role-workplace.json`, and `tuning.json` — the layout-pass
data the Narrative Architect lands after human gating
(`narrative-pipeline/CONTEXT.md` §The full loop). The resolver
(`tools/resolver/src/`) turns this into run folders: mints ids, builds
`graph.json`, emits compiling ink, applies review-edit patches.

## Doors
- `tools/resolver/data/tuning.json` — "the single home for tunable game settings" (`narrative-pipeline/CONTEXT.md`)
- `tools/resolver/README.md` — build commands
- `narrative-pipeline/build-loop.md` — the S4 file split, ink-address rule, tag contract

## Hits
Changing data here changes the next run folder, which cascades to reviewed
lines and the Phaser build (see run-folder card). Test trap from
CONTEXT.md rules: the resolver suite runs under `node --test` (`npm test`);
`npx vitest run` collects 0 tests here and looks like a wall of failures.
Lantern's suite is the vitest one.

## Does not hit
`tools/resolver/out-calib/` and `tools/resolver/out/` — build outputs,
disposable, regenerated by every build. Tuning a number there instead of in
`data/tuning.json` vanishes on the next `resolver build`.
